## 一、核心创作思路

### 1. 我们要解决的真实痛点：输入-输出断层

求职者/答辩者的准备过程天然断裂：

```
读懂资料（输入）  →  说不清楚（输出断层）  →  一被追问就卡壳
     ↑ 现有工具只解决左边                    ↑ 右边几乎没人管
```

- 八股题网站给的是**答案**，不是**训练**：背下来换个问法就废；
- AI 对话框给的是**客气**：它总是先夸你两句，再问一个宽泛的问题，练不出真实压力；
- 知乎内容质量高，但它是**长文**：读到了观点，说的时候还是自己的话。

**我们的命题**：知乎的高赞内容不缺，缺的是把它变成"你自己的、能扛住追问的话"。

### 2. 产品闭环：读懂 → 说清 → 被追问 → 查清楚

| 阶段 | 页面 | 关键设计 |
|---|---|---|
| **读懂** | 2. 拆逻辑 | 先给「考察意图 + 3 个核心得分点 + 避坑项」，再开口，避免对着空白麦克风卡壳 |
| **说清** | 3. 模拟练 | 文字/录音作答；**评委按你的回答往下追问**（1–3 轮，可切"温和引导/压力挑战"两种人设） |
| **被追问** | 3. 模拟练 | 追问不是模板题：模型读到你答里的具体名词、数据、前提，再追一层 |
| **查清楚** | 5. 看复盘 | 逐句回指你的原话 + 知乎原话对照；维度分带刻度；一键生成"可直接背诵的满分版" |
| **沉淀** | 弹药库 | 最佳作答提炼成闪卡（30 秒结论 + 3 条论据 + 1 句防杠话术），考前速览/抽背 |

### 3. 三条差异化壁垒

1. **知乎真实语料 + 可核对溯源**
   题库 92 道全部来自知乎真实问题（`question_recommendations` / `question_answers`），308 张观点卡的 evidence **逐字来自来源**并通过校验；界面上每条观点都能**一键打开知乎原文**。
   我们**不说"高赞"**：知乎开放接口的答案只返回 `{Url, Summary}`，没有作者与赞同数 —— 与其编一个"高赞"，不如把原文链接摆出来让用户自己核对。

2. **本地优先的隐私架构**
   服务端**零落盘**：录音、转写稿、简历、复盘、闪卡、台账全部只存在用户浏览器的 IndexedDB。服务端无状态 → 部署到任何机器都不用迁数据，评委可以放心上传自己的真实简历。

3. **抗幻觉的引用校验**
   模型给出的每条结论都必须挂到具体来源编号（S1/S2…），越界引用/无依据引用会被**丢弃并计数**；没有来源的题目直接降级为"规则层诊断"，绝不硬套观点。

## 二、技术实现

### 1. 架构：单容器、单端口、同域

```
浏览器（唯一的用户数据存放处）
  ├─ IndexedDB：录音 / 转写稿 / 简历解析 / 复盘报告 / 闪卡 / 台账
  ├─ Web Speech API：实时字幕（可选本地 ASR 转写兜底）
  └─ fetch ──► Node BFF（Hono）—— 同域同时托管静态站与 /api，无 CORS
                 ├─ /api/coach/*      复盘、追问、润色（SSE 流式）
                 ├─ /api/resume/*     简历解析、要点出题
                 ├─ /api/defense/*    答辩追问、专项追问
                 ├─ /api/explain/*    资料详解、视频链接解析
                 ├─ /api/zhihu/*      知乎检索（配额 + 熔断 + 缓存）
                 └─ /api/auth/*       知乎 OAuth（可选）
```

### 2. 几个关键工程决策

| 决策 | 原因 |
|---|---|
| **数据全在浏览器，服务端零落盘** | 隐私是产品承诺（也是评审最关心的合规点）；顺带让部署无状态、可随时迁移 |
| **同域单端口托管** | 规避 CORS；录音 `getUserMedia` 需要安全上下文，平台给的 HTTPS 域名直接可用 |
| **确定性规则层 + 模型层双轨** | 10 条原话级规则零成本、零幻觉、可解释；模型层负责语义理解，缺来源时只跑规则层并**显式降级** |
| **评分维度按题型分流** | 技术题评「技术深度 / 工程权衡 / 边界意识」，软素质题评「结构清晰 / 证据充分 / 表达分寸」—— 避免给"考公怕面试"打"技术深度 38 分"这种错位分 |
| **SSE 流式 + 阶段文案** | 复盘要 10–60 秒；流式阶段播报（"正在检索知乎回答结构… → 正在提炼核心考察点… → 正在逐句诊断…"）把等待变成可见进度 |
| **模型调用层加固** | 并发闸门（默认 3，超出排队）、超时/5xx/429/JSON 解析失败重试 1 次、客户端断连中断上游、用量统计 |
| **公网分享口令** | `PUBLIC_SHARE_TOKEN` + `x-share-token`：链接给评委，陌生人打不进来，额度不被打爆 |
| **数据版本化** | 备份带 `SCHEMA_VERSION`，导入校验并迁移旧结构；录音默认只导出文字稿 |

### 3. 质量保障

- **前端冒烟 9 条**（playwright-core + 本机 chromium）：首页 / 筛选分页 / 拆逻辑 / 作答门禁 / 领域样例 / 复盘维度 / 弹药库工具条 / 答辩守卫 / 全程无 JS 报错；
- **后端 11 条单测**：规则命中、转写解析、双轨对齐、引用校验、PDF 质量判定；
- **类型检查 0 错**（strict + ES2024 lib）。

### 4. 数据规模（实测）

| 指标 | 数值 |
|---|---|
| 真题 | 92 道（tech 82 / soft 10），7 个方向每档 ≥9 道 |
| 方向 | ai-agent 15 / rag 12 / backend 11 / algo-data 20 / product 9 / general 10 / defense 15 |
| 难度分布 | 基础 17 / 进阶 47 / 难 28 |
| 观点卡 | 308 张，覆盖 90/92 题，evidence 逐字校验 308/308 通过 |
| 抓取成本 | 推荐接口 39 次 + 回答接口 98 次（两个配额桶独立），LLM 生成观点卡约 130 次尝试 |

## 三、与知乎社区生态的契合度

1. **用知乎的内容做语料，而不是蹭知乎的流量**
   题库 92 道全部是知乎真实提问（"RAG 有哪些优化方案""分布式事务最终一致怎么实现""导师能看出论文是 AI 写的吗"…），
   观点卡全部来自知乎真实回答并**逐字校验**。我们把知乎的长回答压缩成"可背诵的 3 步框架"，这是知乎内容在**求职/答辩**场景的二次分发。

2. **用知乎的开放能力做技术底座**
   全程使用知乎开放平台（`question_recommendations` / `question_answers` / 搜索）作为唯一内容来源，
   并遵守配额与熔断策略（按自然日配额、60 秒熔断、磁盘缓存、stale-while-error）。

3. **用知乎账号体系做身份（可选）**
   接入知乎 OAuth 后，顶栏显示「知乎 · 昵称」；但**我们不设登录墙** —— 评委打开即用，登录只是身份标记，
   也因此不需要提供测试账号密码。

4. **反哺社区**：每张观点卡都带原文链接，用户可以跳回知乎看完整讨论、继续深挖 —— 我们是知乎内容的**放大器与练习场**，不是内容的替代品。

## 四、场景价值与后续落地设想

### 场景价值

| 人群 | 痛点 | 本项目怎么帮 |
|---|---|---|
| 校招 / 社招求职者 | 背了八股，遇到追问就露怯 | 按**你简历上的真实经历**出题，评委顺着你的回答往下追 |
| 准备毕设 / 开题的学生 | 评委问的正是方法边界与对照实验 | 上传论文即可生成"创新点会被怎么质疑"，并给出实验设计的缺口 |
| 技术团队内部演练 | 模拟面试成本高、反馈主观 | 用团队自己的材料生成刁钻问题清单，人工过一遍就是一次评审预演 |
| 转岗 / 跨领域求职者 | 不知道目标岗位问什么 | 按 JD 生成 3 道定制题，先看框架再练 |

### 后续落地设想

- **题库持续供给**：抓取脚本已参数化（`--domain` / `--urls` / 每日配额分桶），可做成定时任务持续补充；
- **多人协作**：把"闪卡 + 薄弱点"做成可导出/导入的**团队知识卡组**（已有 JSON 导出与 schema 版本迁移）；
- **浏览器插件**：把"拆逻辑"与"追问"做成侧边栏，面试当下就能查自己的话术卡；
- **知乎生态联动**：把高频追问反哺成知乎问答专题（"面试官追问『口径是什么』时到底在考什么"）；
- **技术延展**：本地优先 + 服务端零落盘的模式可直接复用到企业内部面试系统（简历不出内网）。

### 下一步（提交后 1 个月内可做）

1. 题库补到 200+ 并按真实使用数据排序；
2. 接入语音评测（停顿、填充词、语速）与更多面试官人设；
3. 把答辩预测接到论文 PDF 的公式级解析；
4. 小范围内测（20–50 人），用"追问命中率"评估效果。
