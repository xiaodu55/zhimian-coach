- 题库 JSON 里的 11 位数字（如 `15764658xxx`）是**知乎问题 ID**（`question/15764658xxx`），不是手机号。
- 提交里的 32 位十六进制串是 commit sha 与 cpolar 隧道 ID。

### 🕳 仍需你手动处理的一项（GitHub 平台行为，我无法代做）

**强制推送后，旧提交对象在 GitHub 上仍可通过 SHA 访问一段时间**（悬空对象，GitHub 延迟 GC）：

```
旧提交 99e3d572…  →  https://api.github.com/repos/xiaodu55/zhimian-coach/commits/99e3d572  → 200
```
- 好消息：该提交的**文件内容已经脱敏**（真实姓名/简历文件名在旧 blob 里也已被 replace-text 清掉，实测 raw 拉取 grep = 0 处）；
- 残留的只是**提交作者元数据里的旧邮箱（已脱敏）**。

**处置办法**（GitHub 官方流程）：
1. 打开 <https://support.github.com/contact> → 选 "Sensitive data removal"（或走 <https://github.com/support> → Report a vulnerability / 泄露数据）
2. 说明：仓库 `xiaodu55/zhimian-coach` 曾误提交含个人邮箱的历史，已 force-push 重写，请协助清除悬空对象。

或者：等 GitHub 自行 GC（时间不确定，不建议等）。

- 部署完成后请轮换 `LLM_API_KEY` 与 `ZHIHU_ACCESS_SECRET`，然后重跑
  `node scripts/deploy/build-delivery.mjs` 重新生成并重新上传 —— 旧包里的密钥随即失效。
