# 部署指南（提交「可运行体验链接」用）

> 官方口径来自黑客松官网 FAQ（2026-11-18 抓取）：
> **「我需要自己部署服务吗？」→ 需要。**
> - 架构复杂、多中间件（Redis / MySQL / 消息队列）的项目 → **推荐云主机部署**；
> - 常规项目 → 推荐 **CloudBase** 等一站式部署平台，开箱即用、免运维；
> - **前端 + Node 后端、不含数据库写入的全栈项目 → 可使用知乎 [AiWorks](https://www.zhihu.com/project-square) 提供的部署能力。**
>
> 提交材料要求：**「可运行体验链接（必交）」—— 网页类需提供公网可访问的线上 Demo 链接**（建议同时接入知乎 OAuth；有登录功能须给测试账号密码）。
>
> 本项目正好是「前端 + Node 后端、**服务端零落盘**（所有用户数据在浏览器 IndexedDB）」，因此：
> **首选 AiWorks；不想折腾账号就用 CloudBase；再省事就是任意云主机 + Docker。**

---

## 0. 三条铁律（踩过坑的）

1. **必须 HTTPS**。录音功能用 `getUserMedia`，浏览器只在**安全上下文**下给麦克风权限：
   `localhost` 免密，其余**必须是 https 域名**。CloudBase / AiWorks / 轻量云主机都自带 HTTPS 域名；
   用 trycloudflare 隧道也是 https（但域名每次变、且电脑关机就没了，不适合提交）。
2. **密钥只放服务端环境变量**。`LLM_API_KEY` / `ZHIHU_ACCESS_SECRET` 绝不能进前端代码或仓库。
3. **公网必须设分享口令**。不设的话，任何拿到链接的人都能白烧你的模型额度和知乎配额。
   设 `PUBLIC_SHARE_TOKEN=你的长随机串`，评委用 `https://你的域名/?k=你的口令` 打开即可
   （前端会自动把 `?k=` 存进 sessionStorage 并给所有 `/api` 请求带上 `x-share-token` 头）。

## 1. 环境变量清单

| 变量 | 必填 | 说明 | 本地 `.env` 现值 |
|---|---|---|---|
| `LLM_BASE_URL` | ✅ | OpenAI 兼容端点 | `https://api.deepseek.com` |
| `LLM_API_KEY` | ✅ | 模型密钥 | 已配 |
| `LLM_MODEL` | ✅ | 模型名 | `deepseek-v4-flash` |
| `ZHIHU_ACCESS_SECRET` | ✅ | 知乎开放平台令牌（检索/推荐/回答摘要） | 已配 |
| `PUBLIC_SHARE_TOKEN` | 公网必填 | 分享口令；不设 = 任何人可白用额度 | 未设 |
| `PORT` | — | 监听端口，默认 8787 | 8787 |
| `LLM_MAX_CONCURRENCY` | — | 模型并发上限，默认 3（超出的排队） | 3 |
| `CACHE_DIR` / `CACHE_PERSIST` | — | 知乎内容缓存落盘（容器里建议挂卷） | `.cache` |
| `PDF_OCR` | — | PDF 兜底解析（需要额外依赖时关掉） | `1` |
| `ASR_PROVIDER` / `ASR_*` | — | 云端转写；不配则用浏览器端识别 + 手动导入 | `none` |

> 知乎配额按自然日重置：`question_recommendations` 桶实测每天约 40 次、`question_answers` 桶约 100 次（两个桶独立）。
> 演示期间**不要**跑题库跑批脚本，否则答辩/检索会突然降级。

## 2. 路线 A：知乎 AiWorks（官方推荐，最省事）

1. 打开 <https://www.zhihu.com/project-square>，用**参赛的同一个知乎账号**登录 → 新建项目。
2. 选择「全栈项目 / Node 后端」模板；源码仓库填本仓库（`apps/web` 静态站 + `apps/bff` Node 服务）。
3. 在平台的环境变量里填上表里 4 个必填项（**尤其 `PUBLIC_SHARE_TOKEN`**）。
4. 平台会给一个 `*.aiworks.*` 的 **HTTPS 域名** → 直接把它填进提报表单的「可运行体验链接」。
5. 自检清单（见 §6）跑一遍再提交。

> 本仓库的 `Dockerfile` 就是按「容器 + 同域托管静态站」写的，AiWorks 若走容器构建可直接用。

## 3. 路线 B：腾讯云 CloudBase 云托管（Dockerfile 现成）

```bash
# 本地先验证镜像能构建（需要 Docker Desktop 已启动）
docker build -t zhimian:prod .
docker run --rm -p 8787:8787 \
  -e LLM_BASE_URL=... -e LLM_API_KEY=... -e LLM_MODEL=... \
  -e ZHIHU_ACCESS_SECRET=... -e PUBLIC_SHARE_TOKEN=... \
  zhimian:prod
```

然后在 CloudBase 云托管里「自定义镜像 / Dockerfile 部署」，环境变量照上表填，绑定 HTTPS 域名。

**本地跑容器时的两个注意**：
- `.env` 不会被拷进镜像（也不该），所有配置必须走环境变量；
- 想保留知乎内容缓存，加 `-v zhimian-cache:/data/.cache -e CACHE_DIR=/data/.cache -e CACHE_PERSIST=1`。

## 4. 路线 C：任意云主机（腾讯云轻量 / 阿里云 ECS，最低 ¥24/月）

```bash
# 服务器上（假设已装 Docker 与 Docker Compose）
git clone <你的仓库> && cd zhihu
docker compose up -d          # 见 §4.1
```

### 4.1 `docker-compose.yml`（可直接用）

```yaml
services:
  app:
    build: .
    ports: ['8787:8787']
    restart: always             # 崩了/重启后自动拉起
    env_file: ['.env']         # 环境变量单独放 .env，不进仓库
    environment:
      NODE_ENV: production
      PORT: '8787'
      CACHE_DIR: /data/.cache
      CACHE_PERSIST: '1'
    volumes:
      - cache:/data/.cache
    healthcheck:
      test: ['CMD', 'node', '-e', "fetch('http://127.0.0.1:8787/api/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
      interval: 30s
      timeout: 5s
      retries: 3
volumes:
  cache:
```

### 4.2 域名与 HTTPS

```bash
# 用 Cloudflare 免费证书：域名 A 记录指向服务器公网 IP，再套一层代理拿 HTTPS
# 或直接用 Caddy / Nginx + Let's Encrypt
```

### 4.3 防火墙

安全组只放行 **80 / 443**，**不要**放行 8787（公网走 443 反代到容器 8787）。

## 5. 路线 D：先不部署，用本机保活（仅适合"演示当天临时用"）

⚠️ 电脑关机 / 休眠 / 隧道进程退出 → 链接立刻失效（返回 530）。**不适合提交**，只适合自己内部彩排。

### 5.1 一条命令保活（BFF + 隧道自动重启）

```bash
node scripts/dev/keepalive.mjs
```

它会盯住两件事：BFF（`/api/health`）与隧道进程，任一挂掉就自动拉起，并每 60 秒打印一次心跳。

### 5.2 开机自启 + 禁止睡眠（Windows）

```powershell
# 开机自动跑保活脚本
powershell -ExecutionPolicy Bypass -File scripts/dev/install-autostart.ps1

# 禁止电脑睡眠（演示期间非常关键）
powercfg /change standby-timeout-ac 0
powercfg /change standby-timeout-dc 0
powercfg /change hibernate-timeout-ac 0
```

### 5.3 更稳的隧道（云端常驻）

在云主机上跑 `cloudflared tunnel --url http://127.0.0.1:8787`，域名跟着服务器走，电脑关机也不影响；
再配 Cloudflare Named Tunnel 还能拿到**固定域名**。

## 6. 部署后自检清单（提交前逐条点一遍）

| # | 检查 | 怎么验 | 期望 |
|---|---|---|---|
| 1 | 首页能开 | 浏览器打开 `https://域名/` | 首屏 Hero + 题库卡片，无报错 |
| 2 | 后端在线 | 打开 `https://域名/api/health` | `ok:true`、`bankSize:92`、`requiresToken` 与配置一致 |
| 3 | 分享口令生效 | 不带 `?k=` 访问 `/api/bank` | 401 + 明确提示（说明鉴权生效） |
| 4 | 题库可筛 | 首页点各方向 chip | 每个方向都有题（不再有 0 题方向） |
| 5 | 录音可用 | 陪练室点「开始录音」并授权 | 能录音并出字幕（**必须在 https 下**） |
| 6 | 复盘可用 | 作答 → 提交 → 看复盘 | 出维度分（带 `/ 100 分` 刻度）+ 原话诊断 |
| 7 | 知乎溯源可点 | 题卡「看原答 ↗」 | 能打开知乎原文 |
| 8 | 数据本地 | 刷新页面 | 录音/闪卡/复盘记录仍在（说明数据确实在浏览器，没写服务器） |
| 9 | 额度别被白烧 | `GET /api/usage` | 数字正常；分享口令生效时陌生人打不进来 |

## 7. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 录音按钮点了没反应 | 页面不是 https / 非 localhost | 配 HTTPS 域名；`localhost` 开发时正常 |
| 知乎检索突然全失败 | 当天 `question_answers` 配额用完 | 等次日；演示期间别跑题库跑批 |
| 模型全变"规则模式" | `LLM_API_KEY` 未配或上游超时 | 查 `/api/health` 的 `llmConfigured`；上游偶发失败会自动重试 1 次 |
| 链接提交后打不开 | 用的是临时隧道，电脑关机了 | 改用 AiWorks / CloudBase / 云主机 |
| 陌生人把额度烧光 | 没设 `PUBLIC_SHARE_TOKEN` | 设上并用 `?k=` 链接分发 |
| 容器起不来 | 缺 `pnpm-lock.yaml` / `corepack` 不可用 | Dockerfile 已处理；确认基础镜像能拉取 |
| 数据"丢了" | —— | 不会：用户数据全在浏览器 IndexedDB，服务器无状态，重启/换机器都不影响 |
