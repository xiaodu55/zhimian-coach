## 部署（单容器）

```bash
docker build -t zhimian-coach .
docker run -d --rm -p 8787:8787 --env-file .env -v "$PWD/.cache:/data/.cache" \
  -e CACHE_PERSIST=1 -e CACHE_DIR=/data/.cache zhimian-coach
```

- 生产阶段不需要 `tsx`：镜像内 `pnpm --filter @zhimian/bff build` 后直接 `node apps/bff/dist/index.js`
- 同域托管静态站点 → 规避 CORS，且容器平台分配的 HTTPS 域名满足录音（`getUserMedia`）的安全上下文要求
- **缓存落盘**：`CACHE_PERSIST=1` + `CACHE_DIR` 指向**挂载卷**才有意义；容器文件系统是临时的，不挂卷重启即丢
- 未挂卷时退化为纯内存缓存，功能不受影响，只是重启后重新消耗知乎配额

## 数据来源（真实，不是示例）

| 环节 | 接口 | 说明 |
|---|---|---|
| 真题 | `GET /api/v1/user/question_recommendations` | 真人问题（Title + Url）；搜索接口返回的多是专栏文章，**不能当题** |
| 来源 | `GET /api/v1/content/question_answers` | 高赞回答 `Summary/Url/ContentToken`；**接口不返回赞同数与作者**，前端因此不显示赞数 |
| 观点卡 | `POST /v1/chat/completions`（`zhida-fast-1p5`） | 生成立场/摘要/证据句；**证据句逐字校验**，不通过则重试或标 `evidenceVerified=false` |
| 评分 | OpenAI 兼容模型（DeepSeek） | 四维评分 + 追问 + 改进话术，每条结论强制 `refIds`，越界即丢弃并计数 |

当前库内：**38 题 / 15 题带观点卡 / 56 张卡**（`data-raw-bank.json` 为原始跑批产物，`apps/web/data/question-bank.json` 为前端契约格式）。

## 防编造（工程，不是文案）

1. 模型只能引用给定来源集合 `S1..Sn`；
2. 后处理校验 `refIds` 是否全部合法，越界或非推断类缺引用 → **整条丢弃并计数**；
3. `basis` 枚举强校验：模型把理由塞进 `basis` 时，带合法引用则规范化为「外部佐证」并转存 `inferenceReason`，无引用则丢弃；
4. 失败必显式：模型/接口异常 → `degraded=true` + 页面横幅 + 规则层结论照常输出。

## 录音与实时字幕（M2 / M3）

**同时开着飞书 / 腾讯会议时录音会失效吗？**
一般不会 —— Windows 音频是共享模式，多个应用可同时打开麦克风。但有 4 类真实故障，都会导致"录到静音却不报错"：
1. 会议软件把**默认输入**切成它的虚拟设备（腾讯会议/飞书虚拟麦克风）；
2. 声卡驱动开了**独占模式**（专业声卡常见）→ `getUserMedia` 失败或静音；
3. 蓝牙耳机切到 HFP 通话档 → 采样率降到 8/16k，音质变差但不断流；
4. 会议软件改写增益/降噪 → 声音变小。

因此陪练室做了四道保护：
- **输入设备下拉 + 刷新**：显式指定麦克风，绕过"默认输入被切走"；
- **实时音量条 + dB 读数**；
- **连续 4 秒低于 -50dB 的静音告警**（页面红字 + toast，点明"可能被会议软件占用"）；
- 录音只存本机 IndexedDB，可回放确认。

**PDF 解析（三级，先测质量再升级）**
| 引擎 | 何时用 | 本机可用性 |
|---|---|---|
| `pdf-parse` | 默认；有文本层的 PDF | ✅ |
| `local-ocr`（PyMuPDF + RapidOCR） | `pdf-parse` 抽出的文本质量低于 70 分（扫描件常得 0 字） | ✅ 本机有依赖；容器里没有 → 自动跳过 |
| Apache Tika | 配 `TIKA_URL`（自建 `docker run -p 9998:9998 apache/tika`） | 需自建 |
| MinerU | 配 `MINERU_URL`（自建服务） | 需自建 |

质量评估看的是可量化指标：汉字间空格比、乱码率、控制字符、行均长度、重复行比例 —— 前端会显示「用了哪个引擎 + 质量问题」，不把烂文本当真。
实测：图片版 PDF `pdf-parse` 得 **0 字 / 45 分** → 本地 OCR 兜底 **2798 字 / 100 分**。

**陪练室三种练法（可切换，各自记住上次的题）**

| 练法 | 题目来自 | 评分基准 | 适用 |
|---|---|---|---|
| **📚 真题陪练** | 知乎真题库（53 题，38 题带观点卡） | 知乎高赞观点卡（主流 + 分歧） | 练通用高频题、看知乎怎么答 |
| **🧾 简历陪练** | 你上传的简历（PDF/MD/TXT） | **面经来源（知乎真实内容）+ 规则层 10 条** | 让面试官追着你自己的项目问 |
| **🎙 录音复盘** | 本机录音 / 会议转写稿（导入或粘贴） | 规则层 10 条（未绑定题目来源，不跑观点层，界面明说） | 把已经发生的一场对话变成可核对的复盘 |

**录音复盘模块**（与前两种练法解耦，右栏独立）：
设备选择 → 录音 + 实时字幕（可就地编辑/补写、说话人徽标可点改）→ 可选双轨（麦克风=我 / 系统声音=面试官）→ 转写 → **生成录音复盘报告**（0.5s，逐题规则诊断 + 原话定位）。转写稿可一键「带入」真题/简历陪练的作答框。

**录音复盘支持两种输入**：
1. 直接录音 / 实时字幕；
2. **上传自己的录音文件**（webm / m4a / mp3 / wav）→ 服务端本机 ASR（ffmpeg + faster-whisper）转写，带时间戳。
   容器里没有 python/模型时返回 501 + 替代路径（云端 ASR 或本机脚本），不会假装转写成功。

**简历 × 口述对照（这一块的评审价值最高）**：
在「简历陪练」上传过简历后，录音复盘可以直接做对照 —— 简历写的与你嘴里说的是否自洽、哪些主张没提、哪些会被追问击穿。
实测输出示例：*"这段口述与简历没有直接事实冲突，但严重不覆盖简历核心主张：口述只讲了简历未提的校园二手交易平台后端，未涉及 AgentHarbor/HFusionHub 的 Agent 治理、执行安全与评测闭环"*。

**简历陪练**：上传简历 → 抽取 `画像 / 技能 / 项目 / 缺口` → 生成 6–10 道题，**每题挂简历定位符**（`p1¶14`）+ 2–3 条真实面经来源。
- 面经来源同时充当观点层依据：提交回答后，四维评分里的每条结论都带 `[S]` 编号，可点开看面经原文（和真题模式同一套引用校验）
- **结果缓存**：按简历内容哈希缓存 7 天，同一份简历第二次分析 **0.1s 返回**（`cached:true`）；旁边「重新出题」可强制忽略缓存
- **要点优先的简历练习流**：解析后左栏只铺开"简历要点"（紧凑行，不拉长页面）→ 点一条要点 → 右侧出现「当前要点」+ **实时检索到的知乎面经** → 弹出候选题窗口，**按"被问到的概率"降序**（模型给出 0–100 概率）→ 点「练习」开小窗直接作答并看复盘。
- **两步向导（上传后自动弹窗）**：①「选择要练的要点」滑窗（逐题列出 bullets，多选）→ ②「选一道题去练」滑窗（模型按选中要点生成候选题，每题标出来自哪个要点 + 为什么问）→ 选中即进入练习。
- **题目列表 + 练习状态**：解析结果**持久化在本机**（IndexedDB + sessionStorage 双写），刷新/换会话自动恢复，**不用每练一题就重新上传简历**。
  每题带 2–4 个可勾选的 bullet（回答里必须覆盖的点）与「已练」标记；**练过的题仍留在列表里**，列表头显示「共 N 道题 · 已练 M 道」
接地校验：locator 不在简历分段里的题直接丢弃（`droppedByGrounding` 计数），不做"凭空编经历"的题。
简历题**不跑观点层**（没有对应观点卡），只跑规则层 10 条 + 面经参考 —— 界面上明说，避免拿无关观点硬套。

**说话人分离（面试官 / 我）**
- 推荐姿势：**双轨采集** —— 麦克风（我）+「同时录系统声音」（面试官），各自成轨，天然分离。
  勾选后会弹共享选择器，**必须勾"分享音频"**，否则会明确报错而不是静默。
- 实时字幕只能吃浏览器默认输入（Web Speech API 不接受自定义 MediaStream），所以字幕的说话人靠：
  - **手动模式（推荐）**：「我说 / 面试官说」一键切换，后续句子按此归人；
  - **自动模式**：按问句特征、人称词、上一句说话人推断，可能不准 —— 每句都带徽标，点一下即可改成正确的人；
  - 「字幕整理成转写稿」→ 输出 `面试官：… / 我：…`，直接喂给复盘解析。
- 不支持 `getDisplayMedia` 的环境（移动端 / Tauri 桌面壳）会自动禁用双轨并给出提示。

**双轨 → 复盘（转写两条路线）**
1. 页面「转写这两轨」：调 `/api/asr/status`；配了云端 ASR（`ASR_PROVIDER` + `ASR_BASE_URL` + `ASR_API_KEY`）就直接转，两轨分别转写后按时间轴合并成 `面试官：… / 我：…`。
2. 未配置时**不会假装能转**：返回 501 + 明确指引 —— 点「导出两条音轨」，然后在本机跑
   ```bash
   node scripts/asr/local-transcribe.mjs mic.webm system.webm   # 可选 --with-time
   ```
   本机 faster-whisper 转写两轨 → `ffmpeg silencedetect` 校正说话起点偏移 → 同一套 `align.js` 按时间轴合并 → 生成 `transcript.txt`，粘回作答框即可生成复盘。

## 已知边界（诚实标注）

- 录音需 https/localhost（`getUserMedia` 安全上下文约束）；自动化环境未能验证真实麦克风，需真人点一次。
- 实时字幕依赖 Web Speech API：Edge 走 Azure 较稳，Chrome 国内不稳；WebView2/桌面壳不提供。
- `question_answers` 无赞同数 → 观点卡显示「知乎答主」而非虚构赞数。
- 讲解室已端到端验证（上传→分段→BM25 检索→模型仅依据片段作答→引用 chip→无依据显式兜底）。
  **PDF 支持**：`.pdf` 走 BFF 逐页解析（`p{页码}¶{段号}` 定位符），自动折叠中文汉字间空格；扫描件（无文本层）会明确报错，不假装解析成功。
- **答辩预测**（独立页面 `#/defense`）：契约 `POST /api/defense/analyze {title, segments}` → `{degraded, topRisks[], predictedQuestions[{q, why, locator, severity, zhihuRef}], references[]}`；模型按材料真实内容出评委高危追问（可自曝材料里的指标矛盾），每条挂一条真实知乎讨论；知乎检索失败时 `degraded:true` 且不伪造引用。
  - 另有 `POST /api/defense/references` 只取知乎相关讨论（可点击列表）；`POST /api/defense/followup` 生成评委的连续追问（主问题 + 最多 3 轮，问到头了返回 `exhausted:true`）。
  - 预演小窗是**多轮**的：每轮作答后评委顺着你的漏洞继续追，整场对话（`面试官：/ 我：`）最后汇总成一次复盘。
- **讲解室**（`#/explain`）只做"读懂资料"：上传文档 / 粘贴视频链接 → 详解总结（`POST /api/explain/summary`）→ 就地追问。视频链接由 `POST /api/explain/link` 尽力抓标题/简介/字幕轨（抓不到字幕会明说，可粘贴字幕或转写稿）。
- **单元测试**：`pnpm test`（7 条：规则、转写切分、时间戳容忍、双轨对齐、引用校验）。

## 面试 / 答辩场次 → 练习 → 复盘 的闭环

台账里每条场次按状态给出"下一步该做什么"，并把简历练习与录音复盘都挂到这条场次上：

| 状态 | 下一步 | 主行动 |
|---|---|---|
| 待面试 | 上传简历，按这家公司岗位出题练一遍 | `上传简历练习 →` → 陪练室·简历模式 |
| 待复盘 | 上传录音或会议纪要，生成这场面试的复盘 | `上传录音 / 纪要复盘 →` → 陪练室·录音工作台 |
| 已复盘 | 命中 N 条原话级诊断 | `查看复盘报告 →` → 复盘台 |

- 场次上下文通过 `sessionStorage` 跨页传递，陪练室顶部有「🎯 当前场次」横幅（可清除）。
- 简历解析记录与复盘报告都写入 `opportunityId`，台账据此回填「简历已备 / 已复盘」并显示复盘摘要。
- 新增场次是正经表单（公司/岗位/轮次/状态/日期/形式/备注），不再用浏览器原生 prompt。

## 弹药库台账 = 结构化话术卡片库（闪卡）

台账页（`#/ledger`）顶部是**数据安全三件套**，页面中部是**话术闪卡区**：

| 能力 | 落点 | 说明 |
|---|---|---|
| 导出全量数据包 `.json` | 台账顶部 ① | 含 sessions / weaknesses / opportunities / resumeAnalyses / **flashcards**；顶栏「导出数据」也走同一份列表 |
| 导出面试复习手册 `.md` | 台账顶部 ② | `## 闪卡 → ## 薄弱点 → ## 场次台账`，文件名 `面试复习手册-<日期>.md` |
| 存储占用与清理 | 台账顶部 ③ | `navigator.storage.estimate()` 显示本机占用；「清理原始音频，只留文字稿」把录音 Blob 置空、保留字幕与时长（二次确认，不可撤销） |
| 导入恢复 | 台账顶部右侧 | 读取 `.json` 备份，恢复全部本地数据（含闪卡），完成后刷新台账 |

### 闪卡数据流

```
复盘台 review.js ──buildFlashcard()──▶ 闪卡对象 ──dbPut('flashcards')──▶ 本机 IndexedDB
                                                                        │
台账页 ledger.js ──loadFlashcards()──▶ 网格展示 / 抽背 / 已掌握勾选 ◀───┘
```

- 提炼逻辑在 `js/lib/flashcards.js`（纯函数，不碰网络）：
  - **核心结论**：优先取模型的改进话术 `improvements[0].claim`，其次取最高分维度的 `llmScores[].claim`，都没有则用用户作答首句（去掉开头的「我」，截断 80 字）。
  - **支撑论据**：`ruleFindings` 命中的规则名 + 作答里含数字的可核对句子，最多 3 条。
  - **防杠兜底**：`这一点我的数据是 X，边界是 Y，如果条件不成立我会退化成 Z`，X 填入作答里的第一个数字（跳过 P99 这类标识符），没有数字时也给出能直接念的成句。
- 复盘台点「标记薄弱点并加入优先复习」时会顺手提炼一张闪卡（`source: 'review'`）；台账页也可手动新增（`source: 'manual'`）。
- 台账页加载时会把**最近 3 份复盘报告**提炼成**预览**（只展示、不写库），用户点「存为闪卡」才落库，避免自动污染数据。
- **抽背模式**：卡片默认遮住答案，点一下翻面、再点收起；模式记在 `sessionStorage['zhimian.flashcard.recite']`，刷新后仍生效。
- 全部闪卡只存本机 IndexedDB，导出文件由用户自己决定给谁看，不产生任何网络请求。

## 陪练室的"压迫感"与跨模块闭环

- **追问深度（1–3 轮）+ 面试官人设**：温和引导型（顺思路）/ 压力挑战型（直接质疑方案缺陷、抠边界）。提交后模型会顺着你的回答往下追，追问轮数由深度开关控制，追问框里有「看不懂，看解析」与「跳过这轮」。
- **深挖链路**：主问题 → 评委追问 → 再答 → 整场对话（`面试官：/ 我：`）汇总成一次复盘。
- **复盘盲区 → 专项追问**：每条诊断旁一键「生成专项追问（加入答辩预测）」，生成 2–3 条只针对该漏洞的刁钻问题，直接出现在答辩预测页并可立即预演。
- **溯源角标**：参考答题骨架上的每条得分点都挂着可点击的「知乎高赞溯源」角标，点开看原答主观点与原文链接 —— 对抗 AI 幻觉。
- **语速雷达**：复盘台给出「时长 1 分 40 秒 · 语速适中」与一条可执行建议；文字作答时降级为篇幅自检。
- **话术闪卡**：复盘台的「存入我的弹药库」会把最佳作答提炼成「30 秒核心结论 + 3 个支撑论据 + 1 个防杠兜底话术」，台账页支持考前速览 / 抽背模式（遮住答案点一下翻面）。

## 语音输入的工程细节

- **热词纠错**：转写稿进作答框前先纠正高置信度专有名词（B FF → BFF、indexdb → IndexedDB、同音误识），每处改动都告诉用户；默认不改语义。
- **思考停顿保护**：静音 5 秒不再当作"说完了"，提示「按空格继续说 / 按 Enter 发送」，避免边想边说被强行打断。
- **本地优先**：录音、转写稿、简历、闪卡、台账全部只存浏览器 IndexedDB；台账页可一键导出全量 `.json`、导出面试复习手册 `.md`、查看存储占用并清理原始音频（只留文字稿）。

## 界面结构（给人看的动线）

- **顶栏步骤指示器**：`1 选题库 → 2 拆逻辑 → 3 模拟练 → 4 抗压测 → 5 看复盘`，右侧独立的「弹药库」胶囊（数字为空时也显示 0）。

- **跨路由直达不会撞空页面**：没选题就进下游页面时，给「高频热身题一键载入」与「最近记录恢复」。
- **每页底部有下一步主行动条**：不用抬头找导航。
- **题库双入口**：按方向刷真题（方向 / 难度 / 关键词筛选，每题标知乎观点卡来源）｜定制我的项目答辩（粘贴项目或论文摘要 → 本地拆出 3–5 个核心技术点 → 按被问概率生成专属题单置顶）。
- **证据对照抽屉**：点任意溯源角标，左边是你的说法、右边是知乎高赞原话要点，逐句并排。
- **闪卡掌握度**：生疏 / 熟练 / 随时可讲，可只筛「生疏」突击，导出的复习手册按掌握度分组。

## 界面文案原则

- **不暴露内部术语**：规则编号（R1/R10）、模块代号（M11）、"模型降级…"这类工程黑话一律不上屏。
  诊断统一用 `rules/labels.js` 翻译成人话：`⚠️ 追问抗压不足`、`💡 缺少量化结果`、`💡 有数字但没基线`。
- **降级用状态徽章**：`基础追问模式` / `基础出题模式` / `基础版`，技术原因放到 hover 提示里。
- **卡片默认只放行动所需信息**：题库卡片=标题+考察方向+1 条观点摘要（其余收进「展开细节」）；弹药库首屏=闪卡与优先复习（数据安全收成一行工具条）。
- **陪练设置收进浮层**：追问深度与面试官人设放在 `⚙️ 陪练设置` 里，顶部只留模式切换与「换一题」。
- **不剧透**：观点卡默认遮住，点一次只揭 1 条，答完自动全揭晓。

## 数据与口径（评审时可能被追问，先说清）

- **题库规模**：92 道真实知乎题（技术 82 / 软素质 10），7 个方向每档 ≥9 道；难度三档真实分布（基础 17 / 进阶 47 / 难 28）；308 张观点卡，90/92 题都有可点开的知乎原文。
- **题库带结构化字段**：`domain`（方向）与 `kind`（tech / soft）写在数据里，前端**按字段筛选**而不是靠关键词猜；
  `difficulty` 三档真实分布。方向 chip 上直接标题量，0 题的方向直接禁用，不会"点了空白"。
- **评分维度按题型分流**：技术题评「技术深度 / 工程权衡 / 边界意识」，软素质题评「结构清晰 / 证据充分 / 表达分寸」。
  之前所有题都用技术口径，给"考公怕面试"打"技术深度 38 分"是错的。
- **不说"高赞"**：知乎开发者接口的答案只返回 `{Url, Summary}`，**没有作者与赞同数**，所以页面上只写"知乎原文 / 观点摘要"，
  并把原文链接直接摆出来让用户自己核对。
- **离线可演示**：预跑的真实复盘报告存成静态 JSON（`apps/web/data/demo-reports.json`），断网或模型超时也能走完
  「选题 → 练习 → 复盘 → 闪卡」闭环（首屏「🧯 离线演示」按钮）。
- **本地数据有版本**：备份带 `SCHEMA_VERSION`，导入时校验并迁移旧结构；录音默认只导出文字稿，不让备份变成几百 MB。
- **公网可鉴权**：配 `PUBLIC_SHARE_TOKEN` 后所有 `/api` 都要带 `x-share-token`（前端从 `?k=` 自动带），
  防止演示链接被陌生人刷额度。

## 部署（提交「可运行体验链接」）

官方口径：黑客松 FAQ 明确 **需要自己部署服务**，并给了三条路径 ——
架构复杂的走**云主机**；常规项目走 **CloudBase** 一站式平台；
**前端 + Node 后端、不含数据库写入的全栈项目 → 用知乎 [AiWorks](https://www.zhihu.com/project-square) 提供的部署能力**（本项目正是这一类）。

完整步骤、环境变量清单、HTTPS 要求、自检清单与常见坑：**[`docs/部署指南.md`](docs/部署指南.md)**。
选路线 A（知乎 AiWorks）的照点清单：**[`docs/AiWorks部署清单.md`](docs/AiWorks部署清单.md)**。

```bash
# 生成官方交付包（已包含密钥固化与官方校验，一条命令可重复执行）
node scripts/deploy/build-delivery.mjs

# 打印要粘到平台「环境变量」框里的内容（本地自建部署时用）
node scripts/dev/print-env-for-deploy.mjs
# 部署完，一条命令跑完 9 条主链路自检（把 --base 换成你的域名）
node scripts/test/smoke.mjs --base https://你的域名
```

三条铁律：
1. **必须 HTTPS**（录音 `getUserMedia` 只在安全上下文可用）；
2. **密钥只放服务端环境变量**；
3. **公网必须设 `PUBLIC_SHARE_TOKEN`**，评委用 `https://域名/?k=口令` 打开（前端自动带上），否则任何人拿到链接都能白烧额度。

临时保命（本机方案，电脑不能关机）：`node scripts/dev/keepalive.mjs` 自拉起 BFF + 隧道；
`powershell -ExecutionPolicy Bypass -File scripts/dev/install-autostart.ps1` 开机自启并禁止睡眠。

> 本项目的用户数据**全部在浏览器 IndexedDB**，服务端零落盘 → 部署到任何机器都不用迁数据，重启不丢。
